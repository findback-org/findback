# Independently curated held-out set, v1

The curator (`/root/review_hardening`) authored 18 fictional cases and their
expected checks from the public evaluation contract and production input schema.
The scorer implementation author (`/root/linux_verification`) received only
counts, hashes and broad coverage before implementation freeze. No model outputs
were used to write or revise these cases. This is role separation within one
agent team, not a claim of anonymous authorship or external expert validation.

The frozen corpus contains 8 intake and 10 matcher cases, with 98 predeclared
checks. It includes reports from transport, community, creative, accessibility
and leisure contexts. Matcher records use the production comparison shape:
`claim`, `evidence`, `items`, `reviews`, `candidates` and the verification question.
Coarse candidate lists were generated by the existing deterministic helper;
expected model-evidence checks were separately authored from the supplied facts.
Every record and check includes a source-grounded note.

Coverage includes unknown versus explicit fields, relative and absolute time,
corrections, coarse ambiguity, distinctive agreement, contradictory details,
missing observations, missing attachments, urgency, instruction injection,
printed-label confusion, and unsupported identity or confidence. This is a small
purposeful challenge set, not a representative sample of real lost-property use.

Accepted regex aliases were declared before any evaluation output was seen.
They check specified components in specified output fields. An `entries_mapped`
pass shows only that an entry contains the components of at least one supplied
fact family; an entry could still add an unsupported clause. A regex failure can
also be a valid paraphrase missed by the aliases. Forbidden patterns are narrow
affirmative-action, unsupported-identity, observation and confidence tripwires.
They do not detect every possible invention or establish ownership correctness.

The first run must retain every case, raw structured output, failed check and
provider error. Human review should distinguish a missed paraphrase, a debatable
annotation and an actual evidence error. Neither a later alias change nor a
prompt change may overwrite this first result or be reported as an untouched
held-out score. Any such iteration needs a new dataset/scorer version and must
keep the original result.

`held-out-manifest.json` identifies the exact corpus/contract bytes. Its
`scorer_freeze_sha256` is populated only after the independent implementation
author freezes the production adapter, scorer, contract and development corpus.
The corpus itself is frozen before the first model call and will not be changed
to fit development or held-out outputs.
